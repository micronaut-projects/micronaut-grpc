By default, Micronaut for gRPC does not create client stub beans for you: you expose the stubs your application needs using a `@Factory`, as described below. Alternatively, add the `micronaut-grpc-client-processor` annotation processor and inject stubs directly (see <<injectingStubs, Injecting Client Stubs>>).

You can dependency inject a `io.grpc.ManagedChannel` into the factory. Each injected `io.grpc.ManagedChannel` will automatically be shutdown when the application shuts down.

=== Configuring ManagedChannel Instances

The channel can be configured using properties defined under `grpc.client` by default.

For example, if you wish to disable secure communication:

[configuration]
----
grpc:
    client:
        plaintext: true
        max-retry-attempts: 10
----

Properties under `grpc.client` are global properties and are the defaults used unless named configuration exists under `grpc.channels.[NAME]`.

Any property of the `io.grpc.netty.NettyChannelBuilder` type can be configured.

You can also disable all gRPC client channel injection, or disable a specific named client:

[configuration]
----
grpc:
    client:
        enabled: false
----

[configuration]
----
grpc:
    client:
        greeter:
            enabled: false
----

When a client is disabled, optional or nullable `@GrpcChannel` injection points resolve to an empty value, while required injection points fail with a dependency injection error.

For gRPC service-config based retry and resiliency features, you can configure `default-service-config` as a nested map. The map is bound using Micronaut's nested/raw map binding so gRPC service config keys such as `methodConfig`, `retryPolicy`, and `hedgingPolicy` are preserved as-is.

[configuration]
----
grpc:
    client:
        plaintext: true
        enable-retry: true
        max-retry-attempts: 4
        default-service-config:
            methodConfig:
                -
                    name:
                        -
                            service: helloworld.Greeter
                    retryPolicy:
                        maxAttempts: 4
                        initialBackoff: 0.1s
                        maxBackoff: 1s
                        backoffMultiplier: 2
                        retryableStatusCodes:
                            - UNAVAILABLE
----

The same structure can be defined per channel under `grpc.channels.<name>.default-service-config`.

==== TLS and Mutual TLS

A channel can verify the server against your own CA certificates and present a client certificate to servers that require one:

.Configuring TLS for a channel
[configuration]
----
grpc:
    channels:
        greeter:
            address: 'greeter.internal:50051'
            ssl:
                trust-certificates: 'classpath:ca.crt' # <1>
                cert-chain: 'classpath:client.crt' # <2>
                private-key: 'classpath:client.key'
----
<1> PEM-encoded CA certificates that verify the server. Without it, the JVM's default trust store is used.
<2> The client certificate and its PKCS#8 private key, for mutual TLS. Configure both or neither.

Properties under `grpc.client.ssl` are defaults for channels that have no `ssl` settings of their own. Locations accept the `classpath:` and `file:` prefixes. Don't combine these settings with `plaintext: true`.

==== Client Executors

Each channel runs its callbacks, such as `StreamObserver.onNext` of an async stub, on Micronaut's I/O executor. Set `grpc.client.executor` for every channel, or `grpc.channels.[NAME].executor` for one, to the name of another `Executor` bean. For example, to run callbacks on virtual threads:

[configuration]
----
grpc:
    client:
        executor: blocking
    channels:
        greeter:
            executor: io
----

The value can also be an `Executor` instance supplied by a programmatic property source. An unknown executor name fails when the channel is created. The built-in `@GrpcChannel("grpc-server")` channel to the embedded server, used in tests, always uses the I/O executor.

=== Auto Injected Types

By default, each channel will automatically be dependency injected with beans of the following types:

* `io.grpc.ClientInterceptor` - Any client interceptors declared as beans
* `io.grpc.NameResolver` - The configured name resolver

==== Context Propagation

gRPC runs a call's response callbacks, such as `StreamObserver.onNext` of an async stub, on the channel's executor. Micronaut captures the `PropagatedContext` of the thread that starts the call (when `ClientCall.start` runs, which a stub does for you) and makes it current again in those callbacks, so MDC entries, tracing context and other context elements of the caller are available there. Client interceptors see it in their response listeners too, including calls an interceptor completes itself without reaching the server. A callback that already runs inside a propagated context keeps it.

To turn this off, set `grpc.client.context-propagation.enabled` to `false`.

=== Injecting Client Stubs

Add the client processor to the annotation processor path of the module that compiles your `.proto` files:

dependency:micronaut-grpc-client-processor[groupId="io.micronaut.grpc", scope="annotationProcessor"]

For every service class that `protoc-gen-grpc-java` generates, the processor generates a bean factory for its stubs. You can then inject the blocking, async and future stubs with `@GrpcChannel`, by field or constructor:

[source,java]
----
@Singleton
public class GreetingClient {

    private final GreeterGrpc.GreeterBlockingStub greeter;

    public GreetingClient(@GrpcChannel("greeter") GreeterGrpc.GreeterBlockingStub greeter) {
        this.greeter = greeter;
    }
}
----

The channel is resolved and configured exactly as for an injected `ManagedChannel`, including `grpc.channels.[NAME]` configuration, interceptors and service discovery. All stubs of the same channel share one `ManagedChannel`. A stub of a disabled channel behaves like a disabled channel: a `@Nullable` or `Optional` injection point receives no stub.

The generated factories are secondary beans, so a stub bean you define yourself in a `@Factory` takes precedence. Stubs of other code generators, such as the grpc-kotlin coroutine stubs, aren't generated and still need a factory.
